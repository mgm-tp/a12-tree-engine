[#column-visibility]
=== User-Defined Column Visibility

The column visibility panel lets end users show and hide columns at runtime.
It offers one checkbox per column in `content.columns`, apart from the exceptions below.

The action column and the multi-selection column are never listed, as neither is modelled as a column.
The Tree Engine additionally never lists the column referenced by `configuration.hierarchicalColumnRef`: it carries the indentation, the node icon and the expand/collapse toggle, so hiding it would leave the tree un-navigable.
That column therefore always stays visible, and `initiallyHidden` on it is ignored.

==== Configuration

[cols="1,1,3"]
|===
| Property | Type | Description

| `configuration.enableUserDefinedColumnVisibility`
| `true`
| Enables the feature. Unset by default, so existing models are unaffected. Without the trigger element below, nothing renders.

| `column_visibility` element in `subHeaderBox`
| `ElementType`
| Places the trigger in the left or right slot; either one works. Without the flag above, nothing renders.

| `initiallyHidden` on a column
| `true`
| Hides the column on load; the end user can show it again at runtime.
|===

[source,json,options="nowrap",title="Tree Model"]
----
{
  "content": {
    "configuration": { "enableUserDefinedColumnVisibility": true, "hierarchicalColumnRef": "column-1" },
    "subHeaderBox": { "rightSlot": [{ "type": "column_visibility" }] },
    "columns": [
      { "id": "column-1", "name": "Name", "width": 2 },
      { "id": "column-2", "name": "Description", "width": 1, "initiallyHidden": true }
    ]
  }
}
----

[#column-visibility-state]
==== Reading and Setting the State

link:./assets/generated/typedoc/functions/core_store.UIStateSelector.columnVisibility.html[UIStateSelector.columnVisibility] reads the visibility state and link:./assets/generated/typedoc/variables/core_store.Commands.setColumnVisibility.html[Commands.setColumnVisibility] writes it.

The map holds one entry per column, keyed by column id; a column missing from it follows the modelled default.

[NOTE]
====
Because the initial visibility can be defined in the Tree Model through `initiallyHidden`, the initial
`columnVisibility` passed to the Tree Engine should be based on what is defined there.
link:./assets/generated/typedoc/functions/core_view.getInitialColumnVisibility.html[getInitialColumnVisibility] is provided to get it from the Tree Model.
====

"Reset" writes that same map, so the view returns to the modelled state — a column marked `initiallyHidden` becomes hidden again rather than visible.

[NOTE]
====
Dispatching `Commands.setColumnVisibility` goes straight to the store and does not pass through
`onColumnVisibilityChanged`. An application that persists the selection has to do so on this path as well.
====
