[#application-model]
=== Application Model

Please use link:/docs/SME/sme-am-ba-docs/index.html[SME Application Model] or link:/docs/CLIENT/client-documentation-bundle/index.html#/basics/application-model[Client]'s TypeScript interface to structure the Application Model.
The scope of this documentation only covers SME method.

==== Tree Engine Scene

Firstly, upload workspace to SME. In this section, it is assumed that the Application Model has been set up to work with a basic CRUD workflow (with Form Engine, Overview Engine and Relationship Engine).

Then open the module that needs to integrate Tree Engine and add a menu with this state configuration.

[image,options="nowrap",title="Tree Engine menu in Application Model"]
image::assets/images/204_sme_app_model_tree_engine_menu.png[Tree Engine menu in Application Model]

TIP: The key `model` is optional and does not have to exactly match the model name, it exists to make sure this menu is pointing to the correct scene which is configured in Application Model scenes.

Then go into the module flow and add a new Tree Engine scene, here is an example of how the scene looks like:

[image,options="nowrap",title="Tree Engine scene in Application Model"]
image::assets/images/204_sme_app_model_tree_engine_scene.png[Tree Engine scene in Application Model]

TIP: The `REGION_CLEAR` directive is optional.

CAUTION: The _Match Conditions_ section is very important.
The key `model` should match the one defined in menu.

On _Scene Change_ section, add a directive to `On Enter` event.

[image,options="nowrap",title="Tree Engine `VIEW_ADD` directive in Application Model"]
image::assets/images/204_sme_app_model_tree_engine_scene_view_add_directive.png[Tree Engine `VIEW_ADD` directive in Application Model]

TIP: The `VIEW_ADD` should point to the registered Tree Engine container, which is `TreeCRUD` in this case.

CAUTION: The `Models` section is very important.
Tree Model name must be chosen from the selection box.
Please leave `Document Model` field empty.

The rest is configurable, it is possible to change and customize based on business requirements.
After that, save the Tree Engine scene.
The following figure is an example of a flow used in Tree Engine showcase application:

[image,options="nowrap",title="Tree Engine flow in Application Model"]
image::assets/images/204_sme_app_model_tree_engine_flow.png[Tree Engine flow in Application Model]

[#connect-to-other-engines]
==== Connect to Other Engines

Tree Engine exposes a list of sagas via link:./assets/generated/typedoc/variables/extensions_client.TreeEngineFactories.createSagas.html[TreeEngineFactories.createSagas()]
which simplify connection process of the Tree Engine to other engines.

CAUTION: These sagas heavily depend on the _Match Conditions_ in the Application Model.
It is possible to strictly follow the guideline or <<#advanced/unregister-default-engine-sagas,unregister unnecessary ones>> during application setup then build a custom one.

===== Overview Engine

WARNING: We do not support Overview Engine because there has not been any use case whether Tree Engine should connect to Overview Engine.

===== Relationship Engine

Relationship Engine has two types of display:

* Relationship Engine inside Form Engine
* Standalone Relationship Engine

Both types of Relationship Engine share the same configuration with a usual Form Engine. However, for the Standalone Relationship Engine, which will be opened via the "event_add_link", it will come with an extra descriptor which is "engine" => "relationship". This descriptor can be used in the match condition configuration to differentiate between 2 variants.

===== Editing Link Document

If the Relationship Model has a Link Document, it is required to add a scene to handle the Link Document.
The match condition configuration is the same as Form Engine but the model has to point to the Link Document Model instead of the Document Model.

[#activity-descriptors]
==== Activity Descriptors

Tree Engine provides its own CRUD-like functionality for creating, reading, updating, and deleting tree nodes and link documents, independently of the link:/docs/crud/crud-dev-docs/index.html[CRUD component].
When Tree Engine opens a child activity, it constructs the activity descriptor by spreading the current tree activity descriptor and adding scenario-specific keys.
The Application Model _Match Conditions_ of the target scene must align with these keys to ensure the correct scene is activated.

NOTE: *Current state documentation.*
Tree Engine implements CRUD-like functionality (node creation, editing, link management) independently of the CRUD component.
The descriptor conventions described here reflect this independent implementation.
A future Master Detail Component (A12-15815) will unify these conventions across engines.
Until then, this section is the authoritative reference for Tree Engine's current activity descriptor behavior.

NOTE: `engine: "tree"` in the tree master activity descriptor is optional and was made so in v9.0.0 (A12TE-280).
In the current iteration, projects do not need it for the engine to work correctly.

[cols="1,2,2",options="header"]
|===
|Scenario |Added / overridden keys |Matching tip

|View / edit existing node
|`model` (node's document model ref), `instance` (node's document ID)
|Match on `model` to route to the correct Form Engine scene.

|Create new node (child, sibling, or root)
|`model` (document model ref of the new node), `instance: "__NEW__"`
|`instance: "__NEW__"` identifies a new, unsaved document; match on `model` to route to the correct Form Engine scene.

|Add link (`event_add_link`)
|`model` (target node's document type), `instance` (target node's ID), `engine: "relationship"`
|Match on `engine: "relationship"` to distinguish the Standalone Relationship Engine from a plain form activity.

|Edit link document
|`model` (link document model ref), `instance` (link document ID, or `__NEW__` for a new document), `linkForm: "true"`
|Match on `linkForm: "true"` to distinguish the link document form from a regular edit activity.
|===

NOTE: With the new Relationship Engine integration, child and sibling node creation additionally propagate
`parentInstance`, `parentRelationshipName`, and `parentRelationshipRole` (sibling creation also
propagates `predecessor`) into the descriptor, to combine create document and link process into one step. 
These keys are extra payload, Application Model match conditions do not need to include them.

NOTE: When using a SME-generated Master Details Model, the `engine` key in activity descriptors originates from the MDM-generated initial activity descriptor, not from Tree Engine itself.
See link:/docs/crud/crud-dev-docs/index.html#activity-descriptors-mdm[CRUD's Activity Descriptors: With Master Details Model] for the match condition requirements in that context.

TIP: See <<#connect-to-other-engines,Connect to Other Engines>> for concrete Application Model match condition examples for Form Engine, Relationship Engine, and link document scenes.
